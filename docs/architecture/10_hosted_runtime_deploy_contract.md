# Production-сервер и выпуск

## Каноническая цель

Production-команда получает точную цель явно. Использование случайного host,
локальной копии или устаревшего адреса запрещено. Секреты и target-конфигурация
живут вне Git; в репозитории может находиться только безопасный публичный контракт.

## Чтение

Диагностика начинается с подтверждения цели и версии. Базы открываются без
записи; для SQLite применяются `mode=ro` и `PRAGMA query_only=ON`. Чтение не
создаёт schema, WAL/SHM, jobs или служебные записи.

## Выпуск кода

Доверенный Release Runner:

1. принимает только готовый PR с успешной проверкой точного head;
2. повторно проверяет base/head и выполняет один squash merge;
3. подтверждает родителя merge и фактический `main`;
4. для runtime-изменения разворачивает именно merge SHA;
5. проверяет marker версии, состояние сервисов и применимые health-признаки;
6. публикует короткий receipt.

Изменение только документов или GitHub-механики не обращается к серверу.

## Production-данные

Выпуск кода сам по себе не запускает запись бизнес-данных. Такая операция идёт
отдельно через доменный adapter и общий безопасный launcher: preview, проверка
точного кандидата и состояния «до», один submit, readback и recovery reference.

Backup создаётся только когда изменяемые данные нельзя надёжно восстановить из
Git, первичного источника или существующего журнала отката. Способ восстановления
должен соответствовать точной области изменения.

Повторный submit после сетевой неопределённости запрещён. Сначала выполняется
readback той же operation identity.
