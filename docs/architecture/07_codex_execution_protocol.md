# Работа и проверки

Общие границы заданы в [AGENTS.md](../../AGENTS.md). Этот документ поясняет
организацию работы; обязательного маршрута по этапам нет.

## Выполнение

Главный чат отвечает за пользовательский результат. Он работает сам или
привлекает помощников, когда это сокращает работу или даёт полезную независимую
проверку. Поручение содержит цель, границы и достаточный контекст. Один изменяемый
ресурс имеет одного ответственного; независимые чтения можно выполнять параллельно.

Две локальные учётные записи работают с отдельными рабочими каталогами для
параллельных изменений. Продолжение задачи опирается на доступный чат, файлы и
Git; существенный недостающий контекст уточняется у пользователя.

Для связанной задачи обычно достаточно одной ветки и одного PR. Исправления
продолжают тот же PR. Пользовательские файлы вне репозитория не требуют PR.

## Достаточная проверка

Начни с изменённого поведения и его существенных связей. Выбор дополнительных
проверок и независимого ревью зависит от риска; фиксированного числа проверяющих
и обязательного полного прогона нет.

После исправления повтори затронутые проверки. Уже успешный результат годится,
пока код, база и значимые условия проверки не изменились. Повторное ревью
ограничивается исправлениями и оставшимися существенными замечаниями.

GitHub выбирает обязательные проверки по доверенной карте `ci/checks.json`.
Избыточный выбор исправляется в самой карте или границах модулей с доказательством
сохранённого покрытия. Обход красной проверки не заменяет исправление.

## Выпуск и результат

Используй [порядок выпуска](11_github_release_train.md) для изменения кода и
[контракт production](10_hosted_runtime_deploy_contract.md) для рабочих данных.
Уже разрешённые технические шаги не требуют повторного согласования.

Заверши работу проверкой фактического результата в пределах поручения. Короткий
итог сообщает, что изменено, как проверено и что осталось неизвестным или не
выполнено. Историю действий и большие логи пересказывать не нужно.
