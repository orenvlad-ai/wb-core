# Секреты и внешние API

- Токены, пароли, ключи SSH, cookies и полные production-выгрузки не хранятся в Git.
- Локальные секреты остаются в системном или пользовательском хранилище;
  production-секреты — на сервере или в GitHub Environment.
- Клиентский интерфейс не получает секрет, если запрос может выполнить сервер.
- Логи и receipts содержат безопасные идентификаторы и хеши, а не секретные значения.
- Проверка PR выполняется без production-ключей. Ключи доступны только доверенному
  выпуску или явно запущенной production-операции.
- При ошибке авторизации не подставляй другой аккаунт, сервер или старый токен по догадке.

Каждый модуль дополнительно ограничивает нужные ему методы API, область аккаунта,
частоту запросов и допустимые записи.

## Браузерная проверка WebCore

Для браузерных проверок на Mac и сервере разработки используй отдельный аккаунт
Codex и обычную форму входа `https://api.selleros.pro/login`. Пользователь разрешил сохранять
учётные данные этого аккаунта в описанных ниже личных хранилищах и выполнять
вход самостоятельно.

### Mac

На Mac владельца запись находится в связке ключей macOS: generic password,
service `wbc.codex.browser.api.selleros.pro`, account `codex-browser`.
Значение — JSON с `origin`, `username`, `password`; account записи хранилища
не является логином сайта. Локальная инструкция без секретов:
`~/.local/share/wbc-browser-access/README.md`.
Связка ключей Mac не становится доступной при подключении к Linux по SSH.

### Сервер разработки, пользователь codex2

Для `codex2` отдельно настроен файл
`/home/codex2/.config/wbc-browser-access/credentials.json` с полями `origin`,
`username`, `password`. Каталог имеет права `0700`, файл — `0600`, владелец —
`codex2`. Файл находится вне репозитория; читать его могут `codex2` и root.
Это файловое хранилище, а не зашифрованная связка ключей macOS.

Перед использованием прочитай серверную инструкцию
`/home/codex2/.local/share/wbc-browser-access/README.md`. Проверить наличие,
формат и права файла без вывода значений можно командой:

```bash
python3 /home/codex2/.local/share/wbc-browser-access/check_access.py
```

Проверка обычного входа и доступа к странице витрины:

```bash
/srv/wbc/tooling/wb-core-stage5/venv/bin/python /home/codex2/.local/share/wbc-browser-access/check_access.py --login
```

Проверка закрывает свою браузерную сессию. Для диагностики агент читает файл
непосредственно в память собственного браузерного процесса и выполняет обычный
вход. Настроенный доступ не зависит от включённого Mac; копировать его cookies
или профиль браузера не требуется. Это не предоставляет серверной задаче
управление рабочим столом или встроенным браузером Mac.

### Общие правила

Читай запись только в память браузерного процесса и передавай значения полям
входа только после проверки точного origin `https://api.selleros.pro`.
Не выводи значения в переписку, команды, логи, снимки заполненной формы,
артефакты, Git или CI. Не извлекай cookies пользователя и не подменяй сессию
через сервер. При неопределённом результате сначала проверь состояние той же
попытки входа; не отправляй форму повторно вслепую.

После входа проверь целевую страницу и ожидаемый результат реализации.
Доступность `/login` сама по себе не считается браузерной проверкой.
Использование аккаунта не расширяет разрешённые задачей изменения рабочих
данных. Если запись отсутствует, macOS требует разрешение или вход отклонён,
сообщи конкретный блокер; не перебирай другие аккаунты и старые секреты.
