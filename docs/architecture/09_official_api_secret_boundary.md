# Секреты и внешние API

- Токены, пароли, SSH-ключи, cookies и полные production-выгрузки не хранятся в Git.
- Личные секреты остаются в защищённом пользовательском хранилище;
  production-секреты — на рабочем сервере или в GitHub Environment.
- Клиентский интерфейс не получает секрет, если запрос может выполнить сервер.
- Логи содержат безопасные идентификаторы и хеши, а не секретные значения.
- Проверка PR выполняется без production-ключей. Ключи доступны только доверенному
  выпуску или разрешённой production-операции.
- При ошибке авторизации не подставляй другой аккаунт, сервер или старый токен
  по догадке. Сообщи конкретный блокер.

Каждый модуль определяет нужные ему методы API, область аккаунта, частоту
запросов и допустимые записи.

## Браузерная проверка WebCore

Используй существующую учётную запись сайта «Кодекс» через обычную форму
`https://api.selleros.pro/login`. Пользователь разрешил самостоятельный вход;
учётка не расширяет разрешение на изменение рабочих данных.

Единый порядок входа и безопасного чтения личного файла находится в локальном
навыке `~/.codex/skills/wbc-browser-login/SKILL.md`. Прочитай его перед входом.
Секреты и заполненная форма не попадают в вывод, снимки или артефакты. Cookies
не экспортируются, серверный session secret не используется для подмены сессии.

После входа проверь целевую страницу и результат задачи. Уже действующая
авторизация не требует повторного входа.
