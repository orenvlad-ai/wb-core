# Module 52 — История остатков Web Vitrina

## Показатели

- `Остатки общие` — общий канонический остаток;
- `Остатки WB` — подтверждённый остаток на WB;
- `Остатки FBS: всего` и строки активных FBS-складов;
- значения доступны для TOTAL и отдельных SKU, когда есть доказательства.

## Время и качество

Каждая точка связана с рабочей датой, источником, версией и качеством. Ноль
публикуется только как подтверждённый ноль. При неполных компонентах итог может
быть `partial`; неизвестное значение остаётся `missing`.

Текущий остаток не используется для заполнения прошлого. Закрытый день
обновляется только новой точной версией соответствующей даты.

## Запись

Обычный сбор идемпотентно добавляет или подтверждает точку. Исторический
backfill сначала строит точный список дат/SKU/версий, проверяет отсутствие
нецелевых изменений и только затем выполняется отдельной production-операцией.

Публикация использует candidate-first/pointer-last и сохраняет last-good при
неполном кандидате.

Текущий день может показывать в существующих FBS-строках заявленные WB остатки
из одной полной генерации официального каталога и всех привязанных складов.
Подпись качества и время снимка отличают их от физического журнала FF.
Freshness использует действующую политику снимка: 9 часов для выбранного
трёхчасового профиля, 30 минут в прежнем режиме. Обычный ready-snapshot
writer сохраняет точные значения и provenance; после смены рабочего дня они
читаются как сохранённый снимок и не пересчитываются по сегодняшнему FBS.
Общий остаток складывает физический остаток WB и заявленный FBS на том же
публичном наборе SKU. Товарный капитал шести учётных стадий этим не изменяется.

Незакрытая стоимость FBS не скрывает независимое заявленное количество из
полного официального снимка. Такой показ не подтверждает физическое движение,
себестоимость, капитал или закрытие учётного дня.

`fbs_quantity_publication_v1` восстанавливает только пустые ячейки FBS,
физического WB и их суммы максимум за семь дат из сохранённых полных снимков
соответствующего рабочего дня. WB использует именно физическое количество,
без товара в пути, с проверкой исходных строк и привязанной складской версии.
Непустые значения не перезаписываются; конфликт с выбранной генерацией блокирует
операцию. Текущий день дополнительно проверяет свежесть. Историческая точка
сохраняет фактическое время наблюдения, а не становится подтверждением остатка
на конец дня. Preview связывает источник и Ready, apply использует CAS и
before-image, readback проверяет весь план вместе с происхождением значений.
