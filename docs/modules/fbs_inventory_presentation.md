# Склад FF и товарный капитал по снимкам FBS

Этап 5 готовит согласованное чтение через `FbsInventorySnapshot`. Источник
выбирается только явной передачей объекта в `SheetVitrinaV1WebVitrinaBlock`.
Обычное создание блока по-прежнему использует действующий учёт. Настройки,
активного указателя и автоматической публикации этот этап не добавляет.

## Единая версия

Объект фиксирует одну точную дату, полный FBS-кандидат этапа 3, согласованный
FBO-компонент, WB-компонент этапа 4 и остальные опубликованные складские стадии.
Общая цена SKU рассчитывается тем же `build_shared_cost_day`, что и для
финансового и партнёрского отчётов. Чтение не обращается к Lifecycle и не
пересчитывает складскую историю. Сохранённый объект неизменяем; возвращаемые
словари являются отдельными копиями.

Верхняя карточка FBS и FBS-часть «Склада FF» берут количество из одних строк
одного снимка. Итог FF равен FBS + FBO; FBO не прибавляется к карточке FBS.
Резерв и полный физический FBS не объявляются нулевыми — этих данных в
данном источнике нет. В интерфейсе указаны состав, дата и предварительное
качество оценки. Основание строки раскрывается из той же версии, без загрузки
прежней себестоимости через старый адрес детализации.

FF-капитал и средняя агрегируются по SKU и складам из новых FBS/FBO-компонентов.
Их сумма заменяет прежний FF, а не прибавляется к нему. Группа «Товарный капитал»,
общее количество, общий капитал и средняя используют эту же замену. Производство,
Китай → FF, FF → WB, WB и расхождения приёмки сохраняют опубликованные значения.
Общая цена для текущих зависимых показателей использует состав этапа 4:
WB + FF/FBS + FF/FBO. Она отличается от средней по всем стадиям товарного капитала.

## Проверка оставшихся стадий

Чтение `capture_retained_stages` открывает operational SQLite только с `mode=ro`
и `query_only=ON`. Строки бизнес-представления должны быть привязаны к точной
дате и той же опубликованной WB-версии. Капитал WB сверяется с точным денежным
источником; допускается только его штатное преобразование в число с плавающей
точкой в старом представлении. Для дальнейшего суммирования сохраняется Decimal.

Отсутствие строки представления само по себе не означает ноль. Для внутренних
документальных стадий ноль допускается при отсутствии SKU в полном сохранённом
представлении стадии: его строки и оба итога сверяются со всеми строками той же
положительно опубликованной функциональной версии. У WB ноль подтверждается
полным официальным снимком, проверенным адаптером этапа 4. Нет такого основания —
значение остаётся неизвестным. Неполный капитал делает зависимый итог недоступным.

Положительный FBS без согласованной стоимости не получает нулевой цены или
старого FF-капитала. Необработанные документы делают стоимость предварительного
периода недоступной, но само известное количество остаётся видимым. Нулевой
остаток имеет нулевой капитал; при нулевом общем весе средней цены нет.

## Потребители и граница истории

Один явно переданный объект используется действующими обработчиками карточек
остатков, раздела FF и Web Vitrina. Новый путь пропускает прежнюю подстановку
`official_fbs_management_inventory_v1`. Текущие Proxy 3/4 и маржинальность на
единицу пересчитываются по новой общей цене, включая ранее заполненные ячейки.
Нет датированных входов — зависимые значения недоступны. Ранее сохранённые даты
и исходные денежные показатели не меняются. Архивные метрики не возвращаются.

`apps/fbs_inventory_presentation.py` принимает явные `--db`, `--fbs-state`,
`--day` и необязательный `--wb-version`, выводит проверочный JSON. Источники
не изменяются. Все новые результаты имеют `candidate_only=true`. Загрузка
подготовленного объекта в обычный рабочий сервер, окончательная база,
расписание, закрытие дней и фактическое переключение относятся к этапу 6.

Проверки: `apps/fbs_inventory_presentation_smoke.py` и
`apps/fbs_inventory_presentation_browser_smoke.py`; последний проверяет реальные
обработчики FF/карточек, сборку Web Vitrina и отображение в браузере.
