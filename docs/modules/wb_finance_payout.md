# Расчётная выплата WB

В недельном финотчёте «За товар до удержаний» — `forPay` продаж минус
`forPay` возвратов. Комиссия и эквайринг уже входят в эту сумму.
«Расчётная выплата» вычисляется из исходных строк отчёта:
чистая выручка минус все расходы WB плюс возвраты расходов/доплаты.
Наша себестоимость, покрытие себестоимостью и капитализация не меняют выплату.
Показатель может быть отрицательным. Он не подтверждает зачисление в банке;
одна заявка может объединять несколько недель.

`cashbackAmount` и `cashbackCommissionChange` учитываются как расходы со знаком
документа: продажа — плюс, возврат — минус. `cashbackDiscount` не вычитается
повторно. В самостоятельных строках `additionalPayment` положительное значение
означает расход, отрицательное — его возврат. В продаже/возврате эта
корректировка уже включена в `forPay` и повторно не применяется.

Новые недели рассчитываются без дополнительного обращения к API шапок отчётов.
Официальный `bankPaymentSum` используется только для контрольной сверки.

Для ограниченного исправления сохранённой истории зарегистрирован адаптер
`finance_payout_reconcile_v1` общего Production Apply launcher. В запросе нужны
явные runtime/seller/manifest/SHA, список недель и замороженный ответ официального
списка отчётов (`source`, `source_sha256`). Preview читает только текущие
подтверждённые raw-batches, проверяет их хеши и количество против sync, строит
исправления total и SKU, сохраняющие себестоимость/покрытие, и сверяет полный
набор reportId с официальными итогами. Неделя может содержать несколько
подпериодов, например при смене года или месяца.

Apply выполняет один CAS существующих metrics/reconciliation. Before-image,
кандидат и запись операции сохраняются в одной транзакции в
`wb_finance_projection_audit`; raw и себестоимость не перезаписываются.
Неоднозначный результат проверяется только readback той же операции.
