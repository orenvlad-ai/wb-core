# 3. Target contract и смысл результата

- `GET /sheet-vitrina-v1/vitrina` теперь является реальной usable web-vitrina page:
  - canonical entrypoint for the unified `sheet_vitrina_v1` UI; the main tab strip contains only work sections `Витрина`, `Поставки`, `Отчёты`, `Отзывы`, `Реклама`, `Цены`, `Исследования`; `Настройки` is a right-side shell action next to `Выйти` and activates the embedded settings panel inside the same shell.
  - all six complete server-rendered HTML templates (`operator`, `web_vitrina`, `settings`, `instructions`, internal supplier and supplier-safe) plus generated login/forbidden/setup/instruction-error documents receive exactly one final cascade marked `data-sheet-vitrina-ui-system="v1"`. The shared layer owns design tokens, typography and spacing rhythm, control/card/badge/table/modal geometry, focus/reduced-motion behavior and responsive containment; feature markup, JavaScript, route authorization and business semantics remain owned by their existing surfaces.
  - navigation hierarchy is explicit and semantic: main product sections use the largest level, section/group tabs use the middle level and local warehouse/settings/feedbacks/prices/research views use the compact level. Warehouse navigation names its section and detail switchers separately so the visual hierarchy does not depend on DOM position or label length.
  - wide registries and business tables scroll inside their nearest bounded wrapper. Technical identifiers wrap inside their cards, while the document itself remains viewport-bounded; this includes the fixed-layout multilingual internal/safe supplier registries and compact SKU/warehouse values.
  - shell visibility is section-aware: runtime `allowed_sections` controls which work tabs/actions are shown and which matching `/v1/...` APIs are allowed. `settings` allows the settings surface; `settings + manage_users` is required for `Настройки -> Пользователи`. `supply_operator` legacy users map to only `Поставки`; supplier-only users do not receive the full shell.
  - `GET /sheet-vitrina-v1/operator` remains a compatibility entry and renders the same unified shell instead of the former narrow operator-only page; embedded operator-only panels are reserved for the unified tabs and internal compatibility probes
  - compact table header inside `Витрина`: visible source badge `sheet_vitrina_v1`, explanatory ready-snapshot copy, grid-library/row/column diagnostics and `Снимок/Вчера/Сегодня/TZ` technical line are not rendered. The former standalone `Таблица` title is not rendered; the header line is a two-zone layout: the left zone contains the compact dynamic object label and two adjacent independent visual pills: `Снимок: <date/time>` and the short browser-owned `обн: <date/time>`. No incident badge is rendered outside the explicit warehouse legacy disclosure. Both pills use the same base tone; the whole snapshot pill is emphasized only by bold text, the update pill uses regular text, and no nested snapshot substrate is rendered. The right zone remains anchored to the table/header right edge with the compact icon-only load-status lamp, unlabeled in-header controls and `Загрузить` / `Загрузить и обновить`. No visible `Свежесть` / `свеж:` timestamp, freshness state, legacy dot separator or empty freshness container is rendered; server/API freshness truth remains unchanged and available to non-visible refresh regression state. The dynamic object label may ellipsis/truncate with title and must not move the right-side controls/status/action when its text changes from `Итого` to a long SKU label.
  - status next to the load action is a compact lamp immediately left of `Загрузить` / `Загрузить и обновить`, visually attached to data loading. Visible text is not rendered; the accessible title/aria label carries only `Загрузка: идёт`, `Загрузка: успешно`, `Загрузка: ошибка`, `Загрузка: предупреждение` or `Загрузка: нет данных`. Loading is a simple violet pulsing dot with visible opacity/scale pulse; final states are small static green/yellow/red/neutral dots without border, halo, glyphs or other extra graphics. Its semantics remain the last load window only: `today_current` + `yesterday_closed` in `Asia/Yekaterinburg`; the UI must not expose those technical slot names in the header. Old snapshot errors elsewhere in the selected historical table range must not force visible error; errors/warnings inside that latest two-day window still surface truthfully.
  - while `Загрузить и обновить` is running, the header replaces the load status lamp with a compact pulsing loading lamp driven by the existing async job/log polling (`start/queued`, source fetch, prepare/materialize, load/update table, finish). The former long stage-based progress bar is not rendered; after completion the compact indicator disappears and the final semantic lamp stays visible.
  - the adjacent snapshot and update pills use `Снимок: <date/time>` and `обн: <date/time>` without visible timezone or seconds; neither contains a visible freshness token or duplicate timestamp. Semantic load status is an inline lamp left of the load button, not under the button and not as a left-side period/table aggregate. The former bulky `Период`, `Строки`, grid-library and source-diagnostic cards are not separate operator blocks because period is controlled in the header and row counts remain table/internal diagnostics
  - the Vitrina table header does not render a shared Seller-session badge: generic auth cannot represent route, collector and data health. It keeps only compact local table/data facts. Incident/provisional badges and warnings are absent from the ordinary header; server API/audit evidence remains available inside the explicit legacy contour. `Метрики`, period, filters and load controls wrap without overlap at 760px and 560px.
  - compact historical period control stays in the table header line; section/group controls are moved behind the adjacent `Фильтры` button into a narrow one-row rail. The old always-expanded `История` block and the old standalone filter toolbar are not rendered by default. On desktop width, selected date range renders fully without internal ellipsis while there is usable control space; section/group labels render fully after the rail is opened, with narrow-width fallback allowed only after compact padding/spacing has been exhausted.
  - default web-vitrina period is backend-owned and browser-render-only: opening `GET /sheet-vitrina-v1/vitrina` without an explicit history marker selects `date_to=current_business_date_iso(now, Asia/Yekaterinburg)`, `date_from=date_to-13 days`, `default_preset_id=two_weeks`, exactly 14 inclusive dates. Ready snapshot availability may produce truthful blank/partial cells inside that window, but it must not move the default range endpoint to the latest materialized snapshot. Browser `localStorage`, history state and table snapshot cache are not default-period inputs.
  - manual historical period/day URL state requires `history_mode=explicit`. `date_from/date_to` without this marker, invalid `history_mode`, legacy range state and old table snapshot keys are treated as default no-query mode and are cleaned from the browser URL/state without full reload. The browser may draft dates inside the calendar popover, but the authoritative default range is only `historical_access.default_date_from/default_date_to` and `historical_access.selected_date_from/selected_date_to` from page composition.
  - table controls are in the compact table header, not a separate `Фильтры и настройки` / toolbar section: the header keeps period plus a small `Фильтры` button immediately before the load-status lamp/progress/load action; the opened rail contains section/group controls, a dark-theme `SKU-метрики` picker and a bounded `Столбцы` menu. `SKU-метрики` restores the last server-owned manual/preset selection, keeps `Все метрики` as the first service checkbox, orders eligible individual metrics by current SKU presentation order rather than by label/backend option order, applies only after `Показать`, resets to manual all-metrics through `Сбросить`, and narrows only `row_kind=sku` rows. The picker exposes manual selection, saved presets and the preset editor; shown/collapsed metrics are eligible and hidden metrics are excluded. The `Итого` block and non-SKU aggregate rows stay full; SKU separator rows are compact plain-text table separators without pill/capsule framing and are rendered only when a visible SKU metric row remains under them. The `Столбцы` menu contains exactly `Метрика`, `Раздел`, `Даты`: metric and dates are checked/disabled, while section is checked by default and is the only user-toggleable choice. Visible standalone `Поиск`, generic/technical column manager, `Сброс`, `Тип строк`, toolbar `Метрики`, visible `Сортировка` selector and row-count `Итог` block are not rendered. Obsolete browser state from the former toolbar metric selector is ignored safely.
  - the compact `Метрики` button in the Vitrina table header opens one modal popup over the page; its accessible name remains `Настроить метрики`. The former inline/collapsible block below the table, the second SKU table and `Как Итого` are not rendered. Opening or saving changes only presentation preferences and never starts source refresh or a business-data mutation.
  - repeated object/technical identity columns such as `Объект`, object key/type, SKU id/group, metric key and row-level update timestamp are kept in the row/backend model for filtering, ordering, dynamic label and refresh metadata, but are not visible columns and are not offered as user-restorable column controls. The bounded `Столбцы` control never exposes those technical columns. `Метрика` is the first visible sticky column; `Раздел` is the next visible sticky column by default, left-aligned and sized for current Russian section labels; date columns and required business context columns stay non-hideable by the page UI. Hiding `Раздел` removes its header, cells, badges and reserved width so dates immediately follow `Метрика`; it does not change vertical density. All metric data rows use one 33 px rhythm matching the expanded child-row reference, whether `Раздел` is on or off; normal rows, disclosure parents, expanded children and cost rows do not define per-metric height exceptions. Table headers and presentation-only SKU/object separators retain their own semantic height. Restoring `Раздел` returns the existing badge cells without changing row/disclosure truth or metric-row height.
  - custom browser floating controls in the unified shell close on outside click and `Escape`: historical period popover, `Фильтры` rail / `SKU-метрики` picker / bounded `Столбцы` menu, feedbacks date-range picker, prices `Колонки` menu, research SKU/metric multiselects, research date-range pickers and embedded operator stock-report SKU selector. Inside clicks for checkbox multiselects/date-range selection stay inside the control; clicking section/group inside the filters rail closes only the SKU picker and keeps the rail open. The separate metric-settings dialog follows the modal contract instead: backdrop/close/`Escape`, focus trap and focus restoration. These rules are browser-only UX state, not backend/data truth.
  - main table display headers are Russian and start with `Метрика`, optional `Раздел`, then date columns; the former visible `Обновлено` table column is not rendered because freshness is shown in the header/status area. Backend/API row update metadata stays stable for refresh bookkeeping. The row object/scope label is exposed by the dynamic label above the table, which follows the top visible rendered row (`Итого` first, then current SKU/article while vertically scrolling) and does not depend on horizontal scroll. The main table inserts presentation-only separator rows between `Итого` and the first SKU block and between SKU object blocks; those separator rows show the next SKU/object label and do not change row truth or object identity. The separator label itself is horizontally sticky inside the first visible/sticky `Метрика` column zone, stays visible during horizontal table scroll, truncates long SKU labels with title/tooltip, and the separator background/gap may still span the whole row.
  - expanded collapsed metrics render as child rows with a subtle hierarchy guide/indent inside the `Метрика` cell. The parent disclosure remains icon-only and left of the metric name; visible count text such as `ещё N` / `Показать ещё N` is not rendered. The cost metrics `our_wb_unit_cost_rub` / `total_our_wb_unit_cost_rub` render as ordinary metric labels without a dedicated `?` help button, help focus target or policy tooltip markup; their business values and temporal source policy are unchanged.
  - main-table operator projection keeps seller-funnel source keys distinct while removing the duplicated `Просмотры` row from section `Воронка`: `openCount` / `total_openCount` remain source metrics, but are not shown in this funnel section. Visible funnel rows are ordered as `Показы в воронке`, `CTR в воронке`, `Открытия карточки в воронке`; CTR is calculated read-side as `open_card_count / view_count` (or `total_open_card_count / total_view_count` for total rows), uses percent formatting and renders blank when the denominator is blank/zero/null. Search metrics such as `views_current` / `total_views_current` remain in section `Поиск`; the TOTAL row `CTR в поиске средний` is weighted by `views_current` so low-view SKU outliers from source snapshots do not dominate the operator total.

## 3.2 Browser-state boundary

- Browser-side state now exists only as page-local UI state for filters, modal open/focus, transient settings-row selection and internal rendering plus a cache/migration copy of metric presentation preferences and one namespaced `section_visible` boolean for the bounded column control. `Раздел` is visible when that browser-local key is absent; hiding/showing it persists only this presentation choice and never creates server/business truth. The `SKU-метрики` rail picker reads all non-hidden SKU metrics from the SKU projection of the unified logical order: both `Показано` and `Свернуто` are eligible, while `Скрыто` is absent. Beside the show checkbox it exposes a separate `Цвет` checkbox only for a metric that the current draft actually shows. Checked colors use the bounded six-color palette and highlight available SKU/date values and labels, never `Итого` or unavailable/blank cells. Saved presets, last manual/preset selection and ordered `sku_highlight_metric_keys` remain canonical in the same auth-protected server-side user config; applying presentation changes sanitizes unavailable/highlight keys catalog-driven without rewriting preset membership. `localStorage` is only cache/one-time migration fallback for metric presentation and the canonical owner of this page-local section-visibility preference; it is not data truth.
- Historical access state stays query-string-owned on the same route:
  - no query = default rolling two-week preset ending backend-owned `today_current_date`
  - `as_of_date` = one-day historical mode
  - `date_from/date_to` = bounded period mode assembled server-side from materialized ready snapshots plus explicit missing-date blanks for the backend-owned current week
- Namespace is explicit: `wb-core:sheet-vitrina-v1:web-vitrina:page-state:v1`.
- `GET/POST /v1/sheet-vitrina-v1/web-vitrina/user-config` stores metric-presentation payload v4 under the current authenticated WebCore account: one logical `presentation.order`, logical-id keyed `presentation.display`, `presentation.manual`, expanded logical anchors, SKU presets, last SKU selection and ordered highlight keys. Server config wins over `localStorage`. The versioned v2/v3→v4 migration runs once and is idempotent: current saved `Итого` order/status is the basis for every proven common pair and TOTAL-only row; SKU-only rows are inserted in canonical catalog position and keep their saved SKU status when present, otherwise the system default. It preserves presets, selected preset/manual selection, highlights and collapsed/expanded semantics, sanitizes retired keys, writes `unified_presentation_v1`, and never overwrites later manual v4 changes. New/removed/ambiguous catalog entries reconcile safely by logical identity. Initial preset `Анализ` is seeded only before its own marker exists, so an operator may rename, change or delete it without later automatic recreation.
- This state is not data/source truth: it stores only presentation preferences, never metric values, source statuses, tokens or secrets.

All three families and the incident-aware current-planning aliases are now legacy presentation: the central archived-metric boundary excludes them from active catalog, public read, table, filters, settings, picker, activity labels and group refresh. Existing raw snapshots, persisted historical ready rows, incident quantity evidence and API/audit metadata are not destructively deleted or rewritten. The ordinary table exposes only WB total, FBS total, dynamic active FBS facility and raw combined total planning rows. Canonical `stock_*`, WB WAC, product-capital metrics/reconciliation and calculation consumers remain unchanged.

Saved presentation/preset compatibility is catalog-driven. At initialization the browser intersects persisted order/display/expanded-anchor keys with the current server metric list, appends any active missing keys in canonical order and rewrites the local migration cache; ordered highlight keys are additionally intersected with non-hidden, actually selected SKU metrics and the bounded palette limit, then stale cleanup is persisted to server config. Retired keys therefore cannot create dead rows, zero-count picker entries or invisible active color, while unrelated user ordering, visibility choices and saved preset membership survive.

The shared `build_incident_stock_projection` default remains strict: an active historical policy requires `pagination_complete=true` and a stable raw digest. The retained information-only adapter may still evaluate accepted historical incident evidence internally, but its values/reasons are not promoted to ordinary rows or N/A presentation. Missing evidence is never fabricated as zero, and the legacy transition does not restore or rematerialize historical incident quantities.

Provisional cache identity and server-owned quality evidence remain API/audit-only. The ordinary header/cells do not render incident badges, quality pills, incident warnings, accessible incident tooltips or N/A rows. Capital `unconfirmed` remains a separate active semantic state with its existing reason tooltip/ARIA evidence and no permanent yellow/amber cell styling.

The legacy presentation transition does not use Policy Apply, does not invoke
incident rematerialization and has no production-data runner. Existing policy
rows, configured/effective state, ready/raw/evidence/cache and audit records are
read-only inputs and remain byte-for-byte unchanged. The historical
rematerialization runner remains retained compatibility code and is not part of
this migration.

Non-TOTAL SKU separator labels open the same SKU Management flow through the narrow per-SKU read endpoint, with price, exact campaign/placement bid selection and nmID-filtered history in an opaque accessible modal. Section authorization is unchanged; users without `sku_management` do not receive a clickable control.

All operator dialogs in this shell use one visual contract: a fully opaque dark modal card, opaque modal sections, readable contrast and a translucent dimming backdrop above sticky headers. This applies to Ads, Prices and SKU price/bid preview, warning, success and controlled-error states; drawers, dropdowns and selectors are not converted into modals.

Supplier shipment factual-date, financial/CNY upload, exclusion and relink confirmations use the same opaque modal contract. The modal lists exact shipment/invoice, old/new dates or document identity/amount, linked operations and calculated consequences; combined date changes share one dialog. Focus is trapped, Escape and `Отменить` are side-effect free, and the confirm control is disabled after the first activation. Upload success is rendered only from the committed server outcome plus target-shipment readback; `conflict_other_shipment` offers cancel or explicit relink instead of a generic success toast.

## Automatic warehouse/product-capital table reread

Web Vitrina consumes `warehouse_business_projection` only through its read
contract. While the tab is visible it performs a lightweight revision check
every 12 seconds; a same-origin operation may additionally send a
`BroadcastChannel` hint. A changed revision rereads only
`surface=page_composition&include_table_data=1` and replaces the table payload,
preserving selected period, filter rail/values, metric presentation and preset,
expanded metric anchors and both scroll axes. It never calls the full refresh
route and never reloads the page.

Replay uses neutral `Обновляется`. Successful changed cells receive a
short-lived violet site-accent class. Yellow/warning remains reserved for
provisional, incomplete or error state. A status/read failure leaves the
last-good table rendered and exposes the exact retry warning instead of
clearing data.
