# Автоматический каталог и расчётные итоги витрины

С 8 сентября 2026 года состав отчётности берётся из номенклатуры, включая
скрытые товары с сохранённой идентичностью. Старые включённые SKU также
сохраняются: исчезновение записи справочника само по себе не означает выбытие.
Ручной список Balance определяет управляющие настройки, но не охват отчётности.
Добавление товара в номенклатуру автоматически расширяет запросы источников и
строки следующего обновления витрины. Количество товаров не фиксировано.

Один состав используется при запросе данных и построении строк. Отпечаток
каталога и запрошенные SKU сохраняются в диагностике обновления. Неполный или
неоднозначный каталог останавливает новое обновление, сохраняя предыдущий снимок.

## Дневной пул продаж

Полнота рассчитывается по дневному пулу, а источники продолжают опрашиваться
по всему каталогу. Товар включается автоматически при доступном остатке WB/FBS,
остатке на начало дня, заказах или расходах на рекламу. Участие сохраняется до
конца этой даты даже после обнуления остатка. На следующую дату оно определяется
заново. Внутренний склад FF, производство и транзит сами по себе не включают товар.
При неизвестном остатке и отсутствии подтверждённой активности товар остаётся
неопределённым и виден в причинах неполноты. Непринятые или чужие по дате остатки
не используются для исключения товара.

Подтверждённый ноль заказов и рекламы даёт известную нулевую прибыль без
себестоимости. Нулевой доступный остаток без признаков торговли означает «Вне
пула продаж»: отсутствующие входы такого SKU не ухудшают итог и не заменяются
нулями. При появлении заказов, рекламы или остатка SKU автоматически возвращается.

Для 92 SKU, из которых 37 доступны к продаже, а 33 имеют заказы: если у четырёх
остальных подтверждены нулевые заказы и расходы, итог полный. Оставшиеся 55 вне
продажи не создают предупреждение. Знаменатели маржи берутся из операций, а не
из числа товаров в каталоге или пуле.

## Сценарии

| Состояние за дату | Прибыль | Участие в общем итоге |
|---|---|---|
| Заказы и реклама подтверждённо равны нулю | 0; себестоимость не требуется | Учтён |
| Заказов нет, есть расходы на рекламу | Минус расходы; себестоимость не требуется | Учтён, включая числитель маржи на единицу |
| Есть заказы, все входы доступны | Датированный расчёт | Учтён |
| Есть заказы, нет себестоимости | Нет значения с причиной | Исключён из всех трёх показателей; итог помечен неполным |
| Товар в дневном пуле, заказы или реклама не получены | Нет значения с причиной | Аналогично: отсутствие не превращается в ноль |
| Нет ни одного полностью рассчитанного SKU | Нет значения | Не отображать нулевой итог |
| Новый SKU с доступным остатком, источник ещё не обновился | Ожидаются данные | До получения данных отражается в неполном охвате |
| Товар вне продажи, операций нет | Вне пула продаж | Не ухудшает полноту |
| Нет ожидаемого количества или выручки в знаменателе | Соответствующая маржа не определена | Прибыль при этом может быть известна |

Для каждой версии Proxy состав включённых SKU един для прибыли, ожидаемой
выручки и ожидаемого количества. Общая маржинальность равна сумме прибыли,
делённой на сумму ожидаемой выручки. Маржа на единицу равна той же сумме прибыли,
делённой на сумму ожидаемого количества. Усреднять проценты SKU нельзя.

Пользователь выбрал показывать рассчитанную часть при реальных пробелах.
Под числом видна надпись **«Неполный итог»**. Подсказка содержит полный список
исключённых SKU и причин. Машинное описание сохраняет учтённый состав,
исключённый состав и количество товаров. Когда входы появляются, следующий
пересчёт автоматически возвращает SKU и снимает предупреждение.

## Доказанный ноль

Нулевые заказы принимаются только как явные значения источника. Отсутствующая
строка истории заказов не является доказательством отсутствия заказов.

Реклама получает нули для отсутствующих SKU только после проверки полного
списка кампаний и всех ответов статистики за дату. Статистика запрашивается для
статусов 7, 9, 11, включая завершённые кампании, согласно
[контракту WB](https://dev.wildberries.ru/openapi/promotion#tag/Statistika/paths/~1adv~1v3~1fullstats/get).
Кампании в статусе 7 или 11 с последним изменением до начала выбранного дня
по Москве исключаются из запросов: они не могли показываться за дату. Остановка
в течение дня или неизвестное время изменения не исключают кампанию.
Пропущенная ожидаемая кампания, повреждённый ответ, несогласованная детализация расходов
или ошибка запроса не создают нулевых строк.

## Даты и границы

Используются только входы и параметры выбранной даты. Новое правило применяется
с указанной даты перехода; прежние расчёты и закрытая история до перехода не
переписываются. Появление товара сегодня не заполняет его прошлое нулями.
Обновление вчерашнего дня использует то же правило и входы вчерашнего дня.

Изменение относится к аналитической витрине. Оно не активирует рекламные
кампании, поставки, управление ставками или бухгалтерские записи.

Проверки: `apps/web_vitrina_catalog_economics_smoke.py` покрывает каталог 93/33,
рост каталога, скрытый SKU, реальный путь запросов и построения строк, нулевую
активность, рекламный убыток, неполный итог, восстановление входов, идемпотентность
и сохранение предыдущей даты.

`apps/web_vitrina_daily_pool_smoke.py` проверяет пул 92/37/33, продажу до нулевого
остатка, смену даты, достоверность остатков и даты остановки рекламных кампаний.
