# Module 40 — Наша себестоимость WB

## Каноническое значение

`our_wb_unit_cost_rub` — версия себестоимости конкретного `nmId` на рабочую
дату. Значение берётся из подтверждённой складской истории и не заменяется
средним по группе, чужим SKU, текущим значением задним числом или нулём.

До даты начала подтверждённой ежедневной истории допустима только явно
описанная ретроспективная проекция того же `nmId`. После неё используется
канонический daily WB WAC.

## Потребители

- финансовые отчёты и прибыльность;
- Proxy 3/4;
- товарный капитал;
- Partner report и другие явно подключённые read-side.

Потребитель получает значение вместе с датой, версией, качеством и источником.
Отсутствие или конфликт остаются `missing`/`partial`, а не превращаются в ноль.

## Изменение истории

Историческое исправление ограничивается точным SKU, датой и версией. Перед
записью проверяются кандидат, затрагиваемые потребители, состояние до изменения
и восстановление; после записи — количества, суммы и неизменность остальных
данных.

### Явная управленческая оценка истории

`web_vitrina_management_history_v1` — отдельный ограниченный adapter, по
умолчанию preview. Он переносит только пустую себестоимость из зафиксированного
артефакта с собственным значением каждого SKU (TOTAL из того же артефакта),
помечает оценку и вычисляет пустые Proxy по датированным параметрам. Digest
артефакта, а не изменяемый snapshot ID, фиксирует источник оценки. Физический
складской журнал, бухгалтерская себестоимость и финансовые документы не меняются.

Текущие собственные Proxy следуют текущим согласованным входам; при недостатке
входов они unavailable. После закрытия даты сохраняется последний согласованный
снимок. Обычный economic replay сохраняет явно опубликованную управленческую
себестоимость и её provenance, не отключая остальные исторические защиты.

Восстановление ранее неопубликованного дневного столбца требует полных источников
именно этого дня. Factual provenance отделён от оценки; fallback чтения отсутствующего
outer key открывает только столбец с validated closed-day marker и сохраняет
identity выбранного snapshot. Перед apply нужны exact mask, non-target digest,
backup/CAS и свободный полный warehouse job lock, не только короткий write lock.
