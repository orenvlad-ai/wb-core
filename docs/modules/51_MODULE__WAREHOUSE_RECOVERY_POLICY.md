# Module 51 — Восстановление складских данных

## Выбор защиты

Защита соответствует размеру и обратимости изменения:

- точечная запись — before-image или компенсирующее событие;
- серия связанных записей — transaction/undo journal;
- большая публикация — отдельный кандидат и сохранённый last-good;
- изменение схемы или целого хранилища — проверенная полная копия.

Полная копия не создаётся автоматически для каждой операции.

## Безопасный цикл

1. Точно определить target, scope и текущую версию.
2. Построить кандидат без записи.
3. Проверить capacity, locks/writers, состояние до и способ восстановления.
4. Непосредственно перед записью повторить короткую проверку.
5. Выполнить один submit под доменным lock.
6. Сверить тот же operation ID и non-target данные.

Неоднозначный ответ допускает только query-only readback. Новый submit возможен
лишь как новая явно подготовленная операция после доказанного результата
предыдущей.

## Хранение

Копия считается полезной только после проверки чтения, полноты и связи с
исходной версией. Замена backup выполняется candidate-first; last-good удаляется
только после подтверждения новой копии и только по точному пути.
