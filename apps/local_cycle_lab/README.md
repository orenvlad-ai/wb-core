# Локальный стенд источников WBC

Из корня репозитория, Python 3.11+ и зависимости приложения (`openpyxl`):

```sh
python3 -m apps.local_cycle_lab
python3 -m apps.local_cycle_lab --variant zero
python3 -m apps.local_cycle_lab --variant missing
python3 -m apps.local_cycle_lab.smoke
```

Каждый запуск создаёт временную базу, выполняет штатный сбор обеих дат,
derive, CAS-публикацию Ready и чтение опубликованной витрины. `verification`
сравнивает числа и признаки полноты с независимыми ожиданиями из `scenario.json`.
Ошибка проверки завершает команду ненулевым кодом. Формулы и проверки приложения
не подменяются. **Все входы синтетические**; их соответствие реальным ответам
поставщиков пока не подтверждено. HTTP-форматы сверены с текущими клиентами
репозитория, а не с записью production-трафика.

Варианты меняют только рекламу за 23 ноября. `normal`: наблюдаемые расходы 60 ₽,
100 показов, 10 кликов, 2 заказа и 800 ₽ атрибутированной выручки; DRR 7,5%.
`zero`: те же поля в ответе равны нулю, расход 0 ₽, отношения с нулевым
знаменателем остаются пустыми. `missing`: HTTP 503, значения пустые, дата не принята,
сохраняется штатный повтор. Во всех доступных вариантах полный датированный состав
рекламных кампаний не доказан: наблюдаемый ноль **не подтверждает нулевые расходы
всего кабинета**. В конечных ячейках сохраняется `partial / unknown_scope`.

Перед первым сбором стенд выполняет отдельный штатный сбор текущих показателей
на часах 23 ноября. На часах 24 ноября работает штатный rollover. Вчера:
рейтинг 4,6, цена 380 ₽, SPP и proxy 10%, ставка 140 ₽; сегодня: 4,8, 400 ₽,
20%, 150 ₽. Различающиеся числа обнаруживают перенос сегодняшнего значения назад.
Начальные данные не записываются непосредственно в таблицы принятых снимков.
Бизнес-даты и расчётные входы фиксированы; некоторые диагностические timestamps
штатных клиентов (например, ads source_observed_at) используют реальные часы
запуска. Побайтовое совпадение всех метаданных между запусками не обещается.

Finance содержит SKU 101 и SKU 999 вне витрины. Выручка карточки 101 — 400 ₽,
доставка — 4 ₽, эквайринг — 3 ₽. Хранение кабинета — **2 + 9 = 11 ₽**,
включая товар 999. Нельзя сузить исходный финотчёт до карточек витрины.
Исторический display-stock карточки — 12; текущая дата и разбивка по складам
отсутствуют. Отдельная проверка клиента FBS получает 7 единиц размера 9001.
Это разные источники, а не два подтверждения одного складского снимка.

Для сохранения базы между командами передай новый отдельный путь:

```sh
python3 -m apps.local_cycle_lab --state /tmp/wbc-local-normal
python3 -m apps.local_cycle_lab --state /tmp/wbc-local-normal
```

Каталог и начальные наблюдения создаются один раз. Папка должна иметь маркер того
же сценария и варианта. Чужая папка, другой JSON или вариант отклоняются до
открытия базы. Для другого сценария используй другую папку; автоматического сброса
нет. `--scenario /absolute/path.json` позволяет добавить связанные входы и
ожидания. Подтверждение сохранения данных каталога не заменяет будущую проверку
документа, введённого через интерфейс.

JSON-вывод содержит конечные ячейки, их presentation, принятые слоты и покрытие,
проверки, счётчики каждого источника, фаз и размер состояния. `payload_json_bytes`
считает компактный UTF-8 JSON на наблюдаемой границе; `request_body_bytes` — тело
HTTP-запроса либо сериализованный запрос Finance transport. Это не сетевой трафик:
заголовки, TLS, ZIP/CSV и браузер сюда не входят. `calls` включает прямую подачу
данных блокам; `pages` — ответы клиентов, включая терминальный ответ Finance 204.
Повторение строк при разных вызовах учитывается повторно. Setup, bootstrap,
adapter_probes и collect_and_publish показаны отдельно. Размер JSON сценария и
сумма размеров файлов базы/состояния — отдельные величины.

Приложение запускается после очистки окружения с тестовым токеном. В этом процессе
audit hook запрещает соединения, DNS, datagram-send и запуск внешних процессов;
непредусмотренные HTTP-запросы не имеют сетевого fallback. Нарушение, даже пойманное
внутри блока, приводит к ошибке всего запуска. Это ограничение текущего процесса,
а не проверенная изоляция будущего HTTP-сервера и дочернего history-worker.

Полная [карта источников и покрытия](source-map.md) отделяет HTTP-повтор,
прямую подачу данных, сохранённые входы и вычисления. Стенд пока не запускает
девять этапов business-data-cycle: нет канонических Finance daily/weekly,
полного FBS generation, функционального склада и owned History. Он ещё не
предоставляет ручной интерфейс WBC. Успешный Ready нельзя считать полной приёмкой
склада, партнёрского отчёта или серверного цикла.
