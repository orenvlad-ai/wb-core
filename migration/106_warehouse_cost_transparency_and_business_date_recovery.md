## New derived contract

Supplier detail returns a per-invoice-line proof from the same helper used by functional warehouse replay. It records exact document allocations, source/calculation fingerprints and conservation controls. Certification is green only when the closed shipment fingerprints match the version-scoped shipment state in the active immutable version; this evidence survives the shipment's transition into FF. A source change remains yellow until targeted replay publishes a matching version.

The persisted Web Vitrina snapshot remains immutable, but its active-date warehouse presentation is revalidated on every read against current supplier fingerprints. Every materialized warehouse date records the exact functional version that supplied its numeric cells. Read-time certification is rebuilt only when that binding still equals the active version; a newer warehouse version awaiting economics publication makes the old numeric cells explicitly unavailable and the UI suppresses their raw values. This prevents a queued/failed targeted replay or a split warehouse/economics publication from exposing stale green certification; historical closed-date presentation is not rewritten.

That read-time check uses the SKU scope frozen into the ready snapshot, including a SKU later removed from current config and excluding one added only afterwards. Multi-day period reads preserve each exact snapshot's warehouse cell presentation and synthesize an explicit unavailable reason for a missing exact-date snapshot, so historical unknowns never degrade into anonymous dashes or fabricated zeroes.

All rows used by one proof are read inside one explicit SQLite read transaction. The unpaginated registry uses one batch snapshot and compact per-shipment summaries; full line/document proof graphs remain detail-only. Invoice rematch is cost-affecting only when accounting identity/value inputs change: that clears `expenses_complete`, invalidates the old certification and enqueues one targeted request containing both old and new nmID identities. Presentation labels and diagnostics are excluded, so a label refresh after FF receipt neither mutates capital nor queues replay. Once FF acceptance has frozen the append-only receipt identity, a changed rematch or ordinary edit of canonical invoice identity/quantity/value is rejected before shipment persistence pending a separate audited correction flow. Invoice number/date/currency, declared total and checksum status follow the same fingerprint invalidation/replay contract; a checksum mismatch is an explicit fail-closed blocker. Persisted CNY ledger operations recover the owning document status from `source_document_id`, so a deterministic same-date ordering warning remains counted only for a posted document. Flat operator detail and nested persistence payloads produce the same bounded queue revision, so a completed revision cannot swallow a metadata-only edit. Supplier-stage status is evaluated from the selected shipment flow, so a sibling party's aggregate quality cannot upgrade or downgrade it.

Every counted supplier payment/transfer fee must carry a positive factual RUB valuation. A missing or zero valuation blocks the full canonical shipment proof, clears legacy aggregate exact-cost fields in the registry and, once a first payment activated invoice quantity, aborts warehouse publication instead of silently dropping the paid shipment.

Business-day replay uses official `snapshot_date` (or timezone conversion only as a fallback). The coherent timestamp is sampled after the local source read, not before the external WB fetch, and apply rechecks the same business date before mutation and under the write lock. A current-state version is published only when snapshot, completed capture and apply belong to one canonical business date; an emergency rebuild with an older last-good snapshot fails closed, so current supplier/FF sources cannot enter a historical column. Economics backfill owns canonical warehouse stage/total keys in addition to WB cost/Proxy keys: it clears unproved legacy values to unknown with an explicit coverage reason and publishes only dates supported by an exact-date good functional version whose `effective_at` resolves to that same business date. It never carries an earlier version forward; an exact empty version is a proved zero, while a missing exact version is unknown. Pre-cutover and post-cutover gaps have distinct operator explanations.

Coverage status/reason changes are persisted even when the numeric cells already match; only marker/timestamp churn is ignored. One canonical business date is pinned into every economics dry-run fingerprint; apply rechecks it before and after backup, under the write lock and before commit, so crossing business midnight rolls back instead of mixing live/closed coverage. The acceptance flow treats positive canonical WB quantity as the applicability source for WB unit cost, so a stocked SKU cannot be hidden by absent `orderSum`. Financial proof refresh preserves the complete unsaved shipment-card draft and suppresses both line and aggregate proof for locally changed cost inputs until they are saved.

The registry collection, financial-documents response, finance tab and shipment-registry matrix pass through the same canonical proof gate. Aggregate colour follows `exact_cost_status` (not the mutable `expenses_complete` flag alone), while invoice unit price/value labels use the invoice's actual currency. The weekly Finance downstream also requires an exact-date WB daily-cost row and cannot inherit a last-good functional balance for a missing date. Production UI acceptance derives WB-cost applicability from the persisted daily WB contour quantity, including both in-way components, rather than physical `stock_total` alone.

Any product line with missing identity, non-positive quantity or non-positive invoice value blocks the shipment calculation as a whole. A valid sibling line can no longer hide an omitted part of invoice quantity/capital or become falsely certified.

The reusable UI Flow validates live invariants without pinning mutable catalog or shipment facts. Migration-106 controls — exactly 33 WB SKU, 26GN390 Anti-Spy arithmetic/certification, provisional 26GN462, the China/FF controls and exact 17–18 July coverage — run only with explicit `--acceptance-profile warehouse_cost_transparency_20260720`.

## Apply/rollback evidence contract

Production apply uses only the repo-owned warehouse emergency and functional economics runners. Each non-no-op plan requires an exact reviewed fingerprint, current source/ready-snapshot manifest recheck, adequate free space, a coherent `0600` SQLite backup with SHA-256 and `integrity_check=ok`, one atomic transaction and post-apply reconciliation. The economics manifest covers the exact functional version/snapshot/balance set, daily WB costs and effective calculation-parameter versions; it is checked before/after dry-run and again under the ready-snapshot write lock, so a concurrent hourly publication fails before any cell is committed. The second exact apply must be a no-op. Rollback uses the retained runner backup; primary-source table digests before and after must match.
